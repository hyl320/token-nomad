# Project Plan (PLAN.md)

> 这份文件是项目的“战略层”：定方向、划边界、排路线。它几乎不动，只有阶段推进时才微调。
> 它是**总目标**所在，不要和 `HANDOVER.md`（当下施工单）混在一起。
> 换电脑 / 换 IDE / 换对话：把本文件、`AGENTS.md`、`HANDOVER.md`、`DEVLOG.md` 一起放进仓库根目录，新 agent 进场先读本文件了解“要做什么、不做什么”。

## 1. 一句话目标 (One-liner)

[这个项目最终要做成什么，一句话说清。例如：一个 C++20 线程池 + 异步日志库，做出可复现的数字和一个修过的并发 bug。]

## 2. 非目标 (Non-Goals — 写进仓库也不许加)

- [明确不引入的依赖 / 技术]

## 6. 换地方接着做时的检查清单

1. 本文件是否已放进仓库根目录
2. `git status` 是否只改了计划允许的文件
3. 先跑测试，红了先修，不要用新功能掩盖红的 sanitizer
